## About This Repository

This repository started as **`flutter_init`** — a Flutter new-project template.

Originally a starter template centered on `.agent/` and `AI/` for human–AI co-development, it has evolved through multiple stages into its current form.

### Evolution

| Version | Description |
|---|---|
| `flutter_init` initial | Flutter new-project template (.agent/ + AI/) |
| `flutter_init` v2.0 | Clean Architecture support, skill / workflow system |
| `utakata` v0.2.0 | Template logic extracted into a Dart CLI tool (pub.dev: utakata) |
| `utakata` v0.3.0 | CLI promoted to `utakata_code` package, monorepo integration, architecture-agnostic |
| `utakata` v0.4.0 | `AI/architecture/` restructured, dynamic GUIDE.md generation, auto dependency injection |
| `utakata` v0.5.0 (current) | **Full multi-architecture support**, MVVM templates, file-level diff comparison |

## 🤖 AI Agent Integration

Projects generated by `utakata create` automatically include `.agent/` and `AI/` directories.

### `.agent/` — Instructions for AI

Rules and workflow definitions for AI agents (Claude, Gemini, etc.).

```
.agent/
├── rules/flutter.md          # trigger: always_on (always loaded)
└── workflows/                # Slash commands: /validate, /scan, etc.
```

### `AI/` — Single Source of Truth

A shared specification hub referenced by both AI and humans.

```
AI/
├── architecture/
│   ├── arch_definition.yaml  # Architecture definition (layers, naming rules, guides)
│   ├── guides/               # Implementation guides per layer (dynamically generated)
│   └── features/             # Feature templates
├── specs/                    # App specifications & feature definitions
└── snapshots/                # Structure snapshots auto-updated by utakata
```

## 📦 utakata code CLI

```bash
# Install
dart pub global activate utakata
```

| Command | Description |
|---|---|
| `utakata create <app_name>` | Create a Flutter project (with .agent/ and AI/) |
| `utakata feature add <name>` | Add a feature |
| `utakata feature init` | Bulk-generate all features from the plan |
| `utakata plan` | Generate a plan from feature_request.yaml + arch_definition.yaml |
| `utakata scan` | Scan the current directory structure |
| `utakata validate` | Verify naming rules & directory structure (auto-detects architecture) |
| `utakata diff` | Show diff against the plan (directories + filenames) |
| `utakata core` | Generate Core directory structure from arch_definition.yaml |
| `utakata arch list / show / create` | Inspect & manage architectures |
| `utakata status` | Show overall project status & update project_status.yaml |

Details: [pub.dev/packages/utakata](https://pub.dev/packages/utakata)
