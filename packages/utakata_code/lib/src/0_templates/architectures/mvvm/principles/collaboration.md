# 協作ルール — MVVM (3-layer)

## AI と人間の協作ルール

### 1. ファイル作成

- 手動でディレクトリを作成しない。`utakata feature add` を使う
- ファイル名は必ず命名規則に従う
- 1ファイル1クラスを原則とする

### 2. コミットメッセージ

```
feat({feature}): {変更内容}
fix({feature}): {修正内容}
refactor({feature}): {リファクタ内容}
```

### 3. コードレビュー基準

- [ ] 命名規則に従っているか
- [ ] レイヤー間の依存ルールを守っているか
- [ ] ビジネスロジックが Model 層に集約されているか
- [ ] View 層に直接のデータアクセスコードがないか

### 4. AI エージェントが変更を行う際のチェックリスト

1. `AI/specs/application_specification.md` を更新する
2. `utakata check` を実行する
3. `utakata check` で構造を確認する
4. 変更対象層の `GUIDE.md` に従った実装になっているか確認する

### 5. 複数 AI エージェントの並行作業

- 同一フィーチャー内の異なる層を並行して編集してよい
- 異なるフィーチャーは完全に並行作業可能
- `core/` の変更はコンフリクトリスクが高いため、逐次的に行う
