# ステップ3: 仕様の深掘りと厳密化

## 確認観点

### 1. 機能の具体性
- 各機能の入力/出力は明確か？
- 処理フローは定義されているか？
- エラーハンドリングは考慮されているか？

### 2. 画面遷移
- 主要画面はすべて洗い出されているか？
- 画面間の遷移パターンは明確か？
- 戻る/進む操作の挙動は定義されているか？

### 3. データ要件
- 必要なエンティティは特定されているか？
- 各エンティティの属性/型/制約は定義されているか？
- データの永続化方法は決まっているか？

### 4. エッジケース
- ネットワークエラー時の挙動は？
- 空のデータ時の表示は？
- 権限がない場合の処理は？

### 5. 技術選定

> ⚠️ 参照必須: `AI/architecture/guides/common/technology_stack.md`

| カテゴリ | ライブラリ |
|---------|-----------|
| 状態管理 | Riverpod, hooks_riverpod |
| データモデル | Freezed |
| 画面遷移 | GoRouter |
| ローカルDB | Drift |
| UI補助 | flutter_hooks |

2. 失敗時のエラーメッセージは？

### データについて

2. データは端末に保存？クラウドに保存？

### 画面について
1. [画面名]から遷移できる画面は？
2. ローディング中の表示は？
