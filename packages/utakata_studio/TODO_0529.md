# utakata studio — リデザイン計画 (2026-05-29)

> 現行 v0.2.0 からの大規模リデザイン。カラーパレットの刷新と、プロジェクト単位のルーティング再設計を行う。

---

## 1. カラーパレットの刷新

### 課題

現行のアクセントカラーが蛍光色寄りで視認性が悪く、長時間の作業に不向き。

| 現行カラー | 問題点 |
|---|---|
| `accentCyan (#58D4F0)` | 蛍光が強い、眩しい |
| `accentGreen (#3FB950)` | GitHub 系だが彩度が高い |
| `accentRed (#F85149)` | 主張が強すぎる |
| `accentYellow (#D29922)` | 単体では問題ないが全体の蛍光感と合わさると煩雑 |
| `accentPurple (#BC8CFF)` | ネオン的に浮いて見える |

### 方針

- **落ち着いた彩度** — HSL の Saturation を下げ、Lightness を適度に調整
- **シンプルで洗練されたトーン** — IDE/ツール系（JetBrains、Linear、Figma）のような上品なダークテーマ
- **コントラスト確保** — WCAG AA 基準を意識しつつ、目に優しい色調

### 変更対象ファイル

- `lib/core/theme/studio_theme.dart` — カラー定数の全面置換
- 各ウィジェットで直接参照している `StudioTheme.accent*` の色が自動的に反映される

## 2. ルーティング・画面遷移の再設計

### 課題

現在は起動 → 即プロジェクト内のアーキテクチャビューアが表示される構造。
プロジェクトが開かれていない場合の UX が貧弱（「プロジェクトフォルダを開いてください」の空表示のみ）。

### 新しい画面フロー

```
起動
 └─ ランチャー画面（ホーム）
     ├─ 「プロジェクトを開く」→ フォルダ選択 → プロジェクトワークスペースへ
     └─ 「アーキテクチャ管理」→ アーキテクチャ一覧 → 追加 / 編集 / エクスポート
```

#### 2-1. ランチャー画面（新規）

起動直後に表示されるランディング画面。

- utakata studio のロゴ + ブランディング
- **「プロジェクトを開く」** ボタン → `file_picker` でフォルダ選択
- **「アーキテクチャ管理」** ボタン → アーキテクチャ一覧画面へ
- 最近開いたプロジェクト履歴（将来）

#### 2-2. アーキテクチャ管理画面（新規）

プロジェクトに入る前に利用可能。`utakata arch` コマンド群の GUI 版。

- **一覧表示**: 組み込みアーキテクチャ（Clean Architecture, MVVM）をカードで表示
- **詳細表示**: `arch show` に相当 — レイヤー構造・命名規則・ガイドのビジュアルビュー
- **新規作成**: `arch create` に相当 — ボイラープレート生成フォーム
- **エクスポート**: `arch export` に相当 — YAML ダウンロード

#### 2-3. プロジェクトワークスペース（既存の改修）

フォルダ選択後に遷移する、プロジェクト固有のワークスペース。

現在のサイドバー + コンテンツ構成を維持しつつ、以下を追加・強化：

| 画面 | 状態 | 内容 |
|---|---|---|
| Architecture | 既存 | arch_definition.yaml ビューア + レイヤービジュアライザ |
| Features | 既存 | feature_request.yaml ビューア → **将来: フィーチャー追加 GUI** |
| Health | 既存 | CLI コマンド実行パネル (validate / diff / check / scan / status) |
| Dashboard | 既存 | utakata status ダッシュボード |
| **Spec** | **新規** | `application_specification.md` のビューア（Markdown レンダリング） |
| **Structure Plan** | **新規** | `structure_plan.md` のビューア（Markdown レンダリング） |
| Settings | 既存 | CLI パス設定・接続テスト |

## 3. 新規画面の詳細

### 3-1. 仕様書ビューア（Spec）

- `AI/specs/application_specification.md` を読み込み、`flutter_markdown` でリッチレンダリング

### 3-2. 構造計画書ビューア（Structure Plan）

- `AI/specs/structure_plan.md` を読み込み、`flutter_markdown` でリッチレンダリング
- ファイル変更監視で自動リロード
- plan_architecture.yaml のツリー表示との連携も検討

### 3-3. フィーチャー追加 GUI（将来）

- `feature_request.yaml` にフィーチャーを GUI で追加
- `utakata plan` → `utakata feature init` のワンクリック実行
- パーミッション、エンティティ名、アーキテクチャ選択のフォーム

## 4. ルーティング定義（案）

```
/                        → ランチャー画面（ホーム）
/architectures           → アーキテクチャ一覧
/architectures/:id       → アーキテクチャ詳細
/project                 → プロジェクトワークスペース（ShellRoute）
  /project/              → Architecture ビューア
  /project/features      → Features ビューア
  /project/health        → CLI コマンド実行
  /project/dashboard     → ダッシュボード
  /project/spec          → 仕様書ビューア
  /project/plan          → 構造計画書ビューア
  /project/settings      → 設定
```
