# ステップ2: 仕様書草案作成ガイド

## 草案作成の手順

### 1. ヒアリング内容の整理
- 収集した情報をカテゴリ別に整理
- 矛盾点や不明点を洗い出し
- 追加質問が必要な箇所を特定

### 2. 仕様書セクションへの記入

#### 記入対象ファイル
`AI/document/application_specification.md`

#### 必須セクション
1. **メタ情報**: プロジェクト名、バージョン、更新日、作成者
2. **概要**: コンセプト、目的、背景
3. **ターゲットユーザー・ペルソナ**: 主要ペルソナ、課題、シナリオ
4. **ユースケース一覧**: UC-01, UC-02, ...
5. **スコープ定義**: In-Scope, Out-of-Scope
6. **機能要件**: 機能名、説明、受け入れ基準、依存関係

#### 推奨セクション
7. **画面設計**: 主要画面、遷移、ナビゲーション
8. **データ要件**: エンティティ、バリデーション、永続化
9. **非機能要件**: 性能、セキュリティ、アクセシビリティ

### 3. 草案提示のポイント

```markdown
## 仕様書草案（v0.1）

以下の内容でよろしいでしょうか？
修正や追加が必要な箇所があればお知らせください。

### 概要
[ヒアリング内容から作成]

### 主要機能
[機能リスト]

### 確認事項
- [ ] 機能の優先順位は正しいですか？
- [ ] 追加したい機能はありますか？
- [ ] 削除したい機能はありますか？
```
